# حِسبة — نظام إدارة محل التحصيل والمدفوعات

مشروع واحد يحتوي على تطبيق Flutter (سطح مكتب + Android/iOS) وواجهة خلفية بـ NestJS وقاعدة بيانات PostgreSQL.

يتضمن المشروع أيضًا موقعًا تعريفيًا وتسويقيًا مستقلًا داخل `website/` لعرض حِسبة واستقبال طلبات العملاء.

## الحسابات التجريبية

- المدير: `demo` / `demo`
- المستخدم العادي: `shix` / `shix`

> هذه بيانات للتجربة المحلية فقط ويجب تغييرها قبل الاستخدام الحقيقي.

## التشغيل لأول مرة

1. شغّل قاعدة البيانات من مجلد المشروع:

   ```bash
   docker compose up -d
   ```

2. جهّز وشغّل الخادم:

   ```bash
   cd backend
   cp .env.example .env
   npm install
   npm run start:dev
   ```

3. في نافذة أخرى شغّل التطبيق:

   ```bash
   cd frontend
   flutter pub get
   flutter run -d macos
   ```

من قائمة التشغيل في Cursor اختَر **حسبة — تطوير** أو **حسبة — برودكشن**. أو من الطرفية داخل `frontend`:

```bash
flutter run --flavor dev
flutter run --flavor prod
```

وضع التطوير يتصل بـ`http://127.0.0.1:3000/api` وقاعدة `hesba_dev`. وضع البرودكشن يتصل بـ`https://hesba.alien-fit.com/api` وقاعدة `hesba`. شارة أعلى الشاشة بتوضح أنت على أنهي بيئة. على macOS شغّل إعدادات VS Code أو استخدم `flutter run -d macos --dart-define=HESBA_APP_FLAVOR=dev` (أو `prod`)؛ خيار `--flavor` يحتاج إعدادات Xcode إضافية غير موجودة في مشروع macOS.

لـWindows استخدم `flutter run -d windows`، ولـLinux استخدم `flutter run -d linux`، ولـAndroid/iOS استخدم `flutter run -d android` أو `flutter run -d ios`. تفاصيل البناء للموبايل في `frontend/README.md`.

## القواعد المطبقة

- الحد الأقصى لرصيد حساب فوري: 5,000,000 ج.م.
- حد شحن المحفظة: 60,000 ج.م يوميًا و200,000 ج.م شهريًا.
- الرصيد المتبقي يُرحّل تلقائيًا، وعملية إقفال اليوم تثبته كرصيد افتتاحي لليوم التالي.
- استلام المندوب يمكن تسجيله كمعلّق أو تنفيذه فورًا.
- التحويلات بين أصول المحل داخلية ولا تُسجل كمصروف أو ربح.
- إضافة الحسابات والشحن والإيقاف والحذف والإقفال اليومي للمدير فقط.
- الحساب ذو الرصيد أو الحركات لا يُحذف؛ يتم إيقافه للحفاظ على السجل المالي.

## عمليات عملاء المحافظ وInstaPay

- «تحويل لعميل»: يخرج أصل المبلغ من المحفظة، ويدخل أصل المبلغ والعمولة إلى الخزنة المركزية.
- «استلام تحويل»: يدخل أصل المبلغ إلى المحفظة، ويخرج الكاش من الخزنة. يمكن خصم العمولة من الكاش المُسلّم أو تحصيلها منفصلة؛ صافي الخزنة واحد.
- عمولة التحويل من المحفظة: حتى ٢٠٠ جنيه ٥، وحتى ٥٠٠ جنيه ١٠، وحتى ١٠٠٠ جنيه ٢٠. بعد كل ألف كاملة تبدأ الشرائح نفسها من جديد؛ مثلًا ١٢٠٠ جنيه عمولتها ٢٥ و٢٠٠٠ جنيه عمولتها ٤٠.
- عمولة استلام التحويل على المحفظة: حتى ٢٠٠ جنيه ٥، وما فوق ذلك ١٠ جنيه.
- InstaPay: ٥ جنيه للمبلغ الأقل من ١٠٠٠ جنيه، ومن ١٠٠٠ جنيه فأكثر تكون العمولة ١٪ من المبلغ (١٠ جنيه لكل ألف) في الاتجاهين، مع التقريب لأقرب قرش.
- عملية العميل وقيود العمولة قابلة للعكس معًا من سجل العمليات. «شحن محفظة» الإداري يظل منفصلًا عن عمليات العملاء.
- لا يُرسل المستخدم قيمة العمولة في عمليات المحافظ؛ الخادم يحسبها ويضيفها للخزنة تلقائيًا، حتى لو استُخدم مسار «استخدام المحفظة» القديم.

## حساب مكسب QR

- شحن الحساب المباشر والتحويل الداخلي إليه غير متاحين؛ يدخل الرصيد من عملية سحب كاش لعميل.
- العمولة التي يدفعها العميل ١٠ جنيه لكل ألف من مبلغ الكاش المطلوب.
- تخصم مكسب ٢ جنيه لكل ألف من مبلغ الكاش المطلوب عند استقبال التحويل على QR.
- مثال: لسحب ١٠٠٠ جنيه، يحوّل العميل ١٠١٠ جنيه، وتخصم مكسب ٢ جنيه، فيدخل حساب QR مبلغ ١٠٠٨ جنيه ويستلم العميل ١٠٠٠ جنيه كاش.
- عند التوريد أو التحويل من حساب QR تخصم مكسب ٤ جنيه لكل ألف فوق أصل المبلغ.
- صافي المكسب بعد دورة الاستقبال والتوريد الكاملة هو ٤ جنيه لكل ألف: ١٠ عمولة عميل ناقص ٢ استقبال ناقص ٤ توريد.
- كل النسب تعمل تناسبيًا فوق الألف وتُقرب لأقرب قرش.

## هيكل المشروع

- `frontend/`: تطبيق Flutter (سطح مكتب + موبايل).
- `backend/`: REST API مبني بـNestJS.
- `website/`: صفحة العرض والتسويق الجاهزة للنشر كملفات static.
- `docker-compose.yml`: قاعدة PostgreSQL محلية.

`DB_SYNC=true` مناسب للتطوير المحلي فقط. خطوات التشغيل الآمن على السيرفر، الـmigrations، HTTPS والنسخ الاحتياطي موجودة في [DEPLOYMENT.md](./DEPLOYMENT.md).
